Connect an application to an existing local or remote model endpoint without loading a second model.

## Inspect

Use CortexTerm's supplied model-holder and service facts first. One model per machine: borrow the existing compatible holder through the supported sharing path. Do not start Ollama, llama.cpp or another runtime merely to answer a terminal question.

For the application being configured, establish API type, base URL, model name, authentication and target network. A container's localhost is itself. Query the endpoint's documented model or health route with a deadline if allowed; an OpenAI-compatible `/v1/models` route should be used only after compatibility is known. Never print API keys.

## Propose

Preview the application's provider settings. Keep the actual model identity and endpoint; do not replace them with a familiar default. Starting or changing a service remains a user-run action. Do not bind an unauthenticated model API publicly to repair container access.

## Verify

Check the configured application can make its intended request. A model list or open port does not prove generation, streaming or tool calls work. Distinguish endpoint availability, loaded-model readiness and successful application behavior.
