Edit strict JSON objects, arrays, escaping or value types and reject duplicate keys.

Inspect with format `json`. Identify the complete object or array containing the setting. Use double-quoted keys and strings. JSON does not allow comments, trailing commas, bare identifiers, NaN or Infinity.

Keep types unchanged unless the product requires a conversion: `false` is a boolean; `"false"` is a string. Escape quotes and backslashes inside strings. A URL is still a string, not shell code.

Preview one unique old block with the inspect hash. Do not regenerate the entire file to change one value. The helper parses the candidate and rejects duplicate keys; it preserves unrelated text instead of reserializing the document.

Secret-like lines are hidden. Never use `[REDACTED]` as a real replacement value. Open the native editor for those changes.

After the person applies, check the application's schema or configuration command. Read the effective setting after the required reload. A successful JSON parse alone does not establish the application accepted the setting.
